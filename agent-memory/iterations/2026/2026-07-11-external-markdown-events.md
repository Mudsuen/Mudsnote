# 2026-07-11 external Markdown events

## Goal

Keep the Apple Notes-like library responsive to plain Markdown changes made outside Mudsnote without adding polling or undoing the one-validation active-search optimization.

## Baseline

- The library already reused one immutable search session across query and scope changes.
- External Markdown changes became visible only after a source-navigation validation, search reset, or restart.
- Separate iOS project and UI-test changes were already present in the worktree and were left untouched.

## Implementation

- Added `LibraryFileSystemMonitor`, backed by recursive file-level FSEvents over all configured note roots.
- Coalesced events on a utility queue and forwarded only Markdown-file changes or structural directory changes to the main library controller.
- External changes invalidate the active search session and movable-note cache, evict affected loaded-note entries, and refresh the current list through the existing background index-validation path.
- A selected note reloads from disk only when the editor is clean, preserving in-progress edits.
- Folder structure events reuse the existing deferred background source-folder loader.
- Internal save, move, restore, delete, and folder operations register their affected paths for two seconds so their own FSEvents do not reload the editor or move the caret.
- Added a loading guard for deferred tag discovery so repeated show paths do not start duplicate index work.

## Verification

- Focused tests passed for:
  - real FSEvents delivery after an external Markdown creation
  - active-search-session invalidation and result refresh
  - clean selected-note reload after an external edit
  - suppression of the event generated by an internal save
- Full Swift suite: 127 tests passed.
- `git diff --check`: passed before documentation updates.
- `./scripts/package_app.sh`: installed the production app at `/Applications/Mudsnote.app`.
- `codesign --verify --deep --strict --verbose=2 /Applications/Mudsnote.app`: passed.
- Installed isolated-library smoke:
  - one `Mudsnote 笔记` window remained open
  - search stayed set to `External`
  - writing `External Added.md` outside the app produced a visible result row with its preview without navigation or restart
  - selecting that note and rewriting the same file changed the visible title to `External Updated` and body to `Body changed outside the app`

## Decision

- Keep filesystem observation event-driven and narrowly filtered.
- Reuse the existing incremental index and snapshot refresh paths rather than creating a second metadata pipeline.
- Treat internal-write suppression as an interaction invariant: autosave must never cause a self-triggered editor reload.
